# CountJar v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Account-based counter platform (Twilio Verify login, workspaces, tokens, v2 API, widgets, badges, pixel, analytics, milestones) with a Tailwind UI.

**Architecture:** Flask app factory in `countjar/`; services (`counters`, `stats`, `notify`, …) hold logic, blueprints (`auth`, `web`, `api`, `embed`) are thin. MongoDB via pymongo; tests use mongomock.

**Tech Stack:** Python 3.14, Flask 3.1, pymongo 4.18, requests, Tailwind CSS v4 CLI (in `tailwind/`, output committed), Alpine.js 3, Chart.js 4, pytest + mongomock.

**Spec:** `docs/superpowers/specs/2026-10-14-countjar-v2-design.md`

## Global Constraints

- Counters per user: 5 (`COUNTER_LIMIT`); workspaces per user: 3; daily writes: 10,000; API 600/min/path/caller.
- Slugs: `^[a-z0-9][a-z0-9_-]{0,63}$`. Phones: E.164 `^\+[1-9]\d{7,14}$`.
- No `.env.example`; no env vars shown in user-facing pages.
- API never authenticates via session cookie. All dashboard POSTs require CSRF token.
- Vercel: root `app.py` exports `app`; no `package.json` at repo root.

## Review Focus

1. Anonymous caller hitting `down`/`set`/`reset` on a public counter → 401, count unchanged.
2. `up?by=1000` without a token on a public counter → 403 (step only).
3. Creating a 6th counter (dashboard or admin API) → refused with clear budget message.
4. Two hits crossing a milestone concurrently → milestone fires exactly once.
5. Webhook target `http://127.0.0.1/…` or `https://10.0.0.1/` → rejected at save time.
