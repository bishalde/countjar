Code examples

Copy-paste examples for the most common jobs. Each one is complete and works as written once you swap in your workspace, counter and token.

Before you start

The examples use a workspace called acme with two counters:

  • visits, a public counter for page views, counted from the browser with no token;
  • signups, a private counter counted from a server with a write token.

Server examples read the token from an environment variable called COUNTJAR_TOKEN, so it never ends up in your code:

{% call code("bash") %}export COUNTJAR_TOKEN=cj_your_token{% endcall %}

Count on a web page

Browser code can be read by anyone, so it must never contain a token. Use a public counter: anyone can count it up by one, and nobody can subtract, set or reset it without a token.

If you only want to show the number, the widget does it in two lines. To use the number in your own design:

"…" : count.toLocaleString()} views; }{% endcall %}{% endcall %} {% endcall %} {% call note() %}In development, React's Strict Mode runs effects twice, so you'll see two counts per page load. Production builds count once. Turning on unique counting also stops repeat counts from the same visitor.{% endcall %}

To read a number without counting, call the counter's URL without /up.

Read a number

Reading is a GET on the counter's URL. Add ?window=24h to also get recent activity:

{% call code("python") %}import requests data = requests.get("{{ base }}/acme/visits", params={"window": "24h"}, timeout=5).json() print(f"{data['count']:,} views, {data['window']['count']:,} in the last day") print(f"{data['window']['unique']:,} different visitors in the last day"){% endcall %}

Private counters need a read token in the Authorization header, just like the server examples above. For a fuller summary use /stats, and for chart data use /history.

Handle errors and limits

Failed requests return a JSON error with a stable code you can check. When you're rate limited, the Retry-After header says how many seconds to wait:

{% call code("javascript") %}async function countUp(path, token, attempts = 3) { for (let i = 1; i <= attempts; i++) { const res = await fetch(`{{ base }}/${path}/up`, { method: "POST", headers: token ? { Authorization: `Bearer ${token}` } : {}, }); if (res.status === 429 && i < attempts) { const wait = Number(res.headers.get("Retry-After") || 1); await new Promise((r) => setTimeout(r, wait * 1000)); continue; } const data = await res.json(); if (!res.ok) throw new Error(`${data.error.code}: ${data.error.message}`); return data; } } const { count } = await countUp("acme/signups", process.env.COUNTJAR_TOKEN);{% endcall %}

Only retry 429 and network errors. Other errors, like 401 for a missing token or 404 for a misspelt counter, will fail the same way every time. Limits and errors lists every code.

Export data

History and events can come back as CSV, ready for a spreadsheet:

{% call code("bash") %}# Daily totals for the last 90 days curl -H "Authorization: Bearer $COUNTJAR_TOKEN" \ "{{ base }}/acme/visits/history?range=90d&format=csv" -o visits-90d.csv # The last 1,000 events tagged with plan=pro curl -H "Authorization: Bearer $COUNTJAR_TOKEN" \ "{{ base }}/acme/signups/events?limit=1000&filter=plan=pro&format=csv" -o pro-signups.csv{% endcall %}

You can also download both from the counter's page in the dashboard.
