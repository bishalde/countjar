Widgets and badges

Show a counter anywhere without writing code: a widget for web pages, an SVG badge for READMEs, and an invisible pixel for emails. All three work with public counters and need no token.

The widget

Add an element with the class countjar wherever the number should appear, and load the script once per page:

Each page load counts one visit and shows the total, animating up from zero. The widget draws inside its own Shadow DOM, so your page's styles don't leak into it and its styles don't leak out. It doesn't set cookies. Like, poll and rating widgets remember a visitor's choice in their browser's local storage, so the button shows what they picked last time.

The Embed tab on each counter in the dashboard builds this snippet for you and shows a live preview as you change the options.

Single-page apps

The script finds widgets when the page loads. If your app adds them later, for example after a route change in React or Vue, ask it to look again:

{% call code("javascript") %}window.CountJar?.scan();{% endcall %}

Widgets that are already showing are left alone, so it's safe to call as often as you like. You can pass an element to only look inside it: CountJar.scan(document.querySelector("#comments")).

Every time the image loads it counts a view, unless you add readonly=1. Badges are sent with headers that tell GitHub's image proxy not to cache them, so the number stays current.

For like counters the badge shows the number of likes, polls show the percentage who said yes, and ratings show the average stars.

Public counters only

Widgets, badges and pixels never use a token, so they only work with public counters. A private or missing counter shows a dash in the widget and “not found” on a badge, and isn't counted.

Counting is rate limited per visitor, to stop one person running the number up. Over the limit, badges and pixels still load but the visit isn't counted.
