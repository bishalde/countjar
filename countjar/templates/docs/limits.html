Limits and errors

What every account gets, how rate limiting works, and what each error means.

Plan limits

Every account is free and gets the same limits:

LimitAmount
Counters5 per account, shared across all the workspaces you own
Workspaces3 that you own. You can be a member of any number.
Counts10,000 a day per account, across all your workspaces. Resets at 00:00 UTC.
Milestones10 per counter
Milestone texts5 a day per phone number
Sign-in codes5 an hour per phone number, and 10 tries at entering them

A count is any change to a counter: up, down, set, reset, like, vote or rate, whether it comes from the API, a widget, a badge or the dashboard. Reading counters, stats and history doesn't count.

The counters in a workspace you've been added to use its owner's allowance, not yours. Deleting a counter frees its slot straight away.

Rate limits

Each token, or each IP address for requests without a token, can make 600 requests a minute to any one URL. Every API response tells you where you stand:

{% call code() %}X-RateLimit-Limit: 600 X-RateLimit-Remaining: 587{% endcall %}

Over the limit you get 429 with the code rate_limited and a Retry-After header with the number of seconds to wait. There's an example of retrying in the code examples.

Badges and pixels have the same per-visitor limit, but they never show an error. Over the limit, a badge still shows the number and the visit simply isn't counted. Widgets call the API, so they follow the API's limits.

Error format

Every API error has the same shape:

{% call code("json") %}{ "error": { "code": "unauthorized", "message": "“down” needs an API token with 'write' permission." } }{% endcall %}

Use code in your program; it won't change. message is written for people and may be reworded.

Common questions

Why did my request return "counted": false?

The request worked, but the number didn't change. Either the visitor was already counted (unique counting, likes, votes and ratings), or the counter is at its maximum (counting up) or minimum (counting down).

Can people inflate my public counter?

Anyone can count up a public counter by one at a time; that's what makes widgets work without a token. Rate limits slow down anyone trying to run it up, and unique counting means repeat visits from the same person don't count. Nobody can subtract, set, reset or use a custom step without a token. If a number must only change from your own code, make the counter private.

Can I rename a counter or workspace address?

No, because the name is part of every URL that uses it. Create a new counter, set it to the old value, and delete the old one. A workspace's display name can be changed in its settings; its address can't.

Why does my count go up twice in development?

React's Strict Mode runs effects twice in development, and some dev servers reload the page. Production builds count once. See counting on a web page.

Can I use it from a static site?

Yes. Use a public counter with the widget, a badge, or a fetch call. None of them need a server or a token.

Does CountJar store visitors' IP addresses?

Yes. Each event keeps the visitor's IP address, together with the location looked up from it and their device, browser and language (see visitor details). Only the workspace owner can see IP addresses. Raw events, IP addresses included, are deleted after 90 days. Repeat visitors are recognised by a keyed fingerprint of the IP address and browser.

How do I get more than 5 counters?

Every account gets 5. Free one up by deleting a counter you no longer need. A poll or rating counter can often replace several normal ones, and custom properties let one counter track many things, such as every issue of a newsletter.
